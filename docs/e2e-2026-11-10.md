# Prompt tests — 2026-11-10

End-to-end runs of the workflow these skills describe: a plain-language request, the skill that
answers it, a real key from the license MCP, and the generated program executed against a real image.

## Prompt

> Write me a Python script that reads barcodes and QR codes from an image file. It should work with
> the current Dynamsoft SDK.

The agent reads `dynamsoft-sdk` (product = DBR, platform = desktop → `capture-vision-desktop`) and
then that skill.

## Runs

| # | Platform | Package | Result |
| --- | --- | --- | --- |
| 1 | Python 3.12 | `dynamsoft-barcode-reader-bundle` 11.6.5000 | decoded 1 QR (`items: 1`, exit 0) |
| 2 | Node.js 24 | `dynamsoft-capture-vision-for-node` 3.6.4003 + models | decoded 1 QR (exit 0) |

All four used a key obtained from `get_trial_license`, and none printed the key.

## Defects the tests found

Every one of these was wrong in the skill text and is now fixed.

| # | Found in | Defect | Fix |
| --- | --- | --- | --- |
| 1 | Python | Imported from `dynamsoft_capture_vision_bundle` while the installed package was `dynamsoft-barcode-reader-bundle` (module `dynamsoft_barcode_reader_bundle`) | Import path follows the installed package |
| 2 | Python | `BarcodeResultItem(item)` raised `TypeError` — current bindings already return concrete items | Cast removed; the per-binding rule moved into `references/languages.md` |
| 3 | Node.js | `CaptureVisionRouter.createInstance()` does not exist | Static `CaptureVisionRouter.captureAsync(path, EnumPresetTemplate.PT_READ_BARCODES)`, plus `terminateIdleWorkers()` to let the process exit |
| 4 | Web | `capture()` was handed a `Uint8Array`; it accepts only Blob / URL / base64 / image element / canvas / video | Input examples corrected |
| 5 | Web | `result.barcodeResultItems` does not exist on these builds | Iterate `result.items` and filter on `EnumCapturedResultItemType.CRIT_BARCODE` |
| 6 | Web | A `desktop` key throws `[License] License mismatch: Browser requested` in a browser | The edition must match the runtime; documented in every license section |
| 7 | Web | Document and MRZ templates are not in the barcode-only bundle (`[-10036] The template name is invalid`) | Called out explicitly: those capabilities need the Capture Vision bundle |
| 8 | Java | `LicenseManager.initLicense` returns `LicenseError`, not `int` | Read `error.getErrorCode()` / `getErrorString()` |
| 9 | Java | `CaptureVisionRouter` is not `AutoCloseable`; `try (…)` does not compile | Plain instance; JDK 17 verified |
| 10 | Java | `EnumPresetTemplate` is an interface of **String** constants, not an enum | Pass `EnumPresetTemplate.PT_READ_BARCODES` straight to `capture(path, template)` |

## What the runs also confirmed

- **One key covers the products.** The key issued for `dcv` / `cross-platform` licensed the
  Barcode Reader **web** bundle without complaint. The MCP now reuses a cached key across products
  when the edition matches (`source: "cache-shared"`), so asking for `dwt` after `dcv` costs no trial
  request.
- **The edition is enforced.** The `dbr` / `desktop` key worked in Python and Node and was rejected
  in the browser — the runtime, not the product name, is what the key is checked against.
- **Quota.** Three tests used two issued keys; the rest were cache hits.
